# Архитектура Пары

## Источник истины

`Schedule` содержит профиль группы, недельные шаблоны `lessons` и `overrides: Map<LocalDate, List<Lesson>>`.

Приоритет:

1. Если дата есть в `overrides`, возвращается её полный список. Пустой список — отменённый день.
2. Иначе проверяется учебный период.
3. Выбирается день недели и фильтруется EVERY/ODD/EVEN относительно понедельника первой недели.
4. Результат сортируется по началу.

Так недельный повтор и календарь месяца не дублируют данные. «Разложить на месяц» означает материализовать этот алгоритм для дат месяца. При будущем импорте фактический месячный календарь следует записывать в overrides, а не угадывать повторения.

## Хранение

`ScheduleRepository` — application-scoped singleton, `StateFlow` для UI, IO-корутины, mutex для изменений и общий lock чтения/записи файла. Данные хранятся в private `filesDir/schedule.json` через `AtomicFile`. Перед записью выполняется тот же валидатор, что при импорте. Неудачный импорт не меняет данные. Повреждённый файл сохраняется отдельной recovery-копией; пользователь видит сообщение.

SAF работает с выбранным URI, не требует доступа ко всему хранилищу. Импорт ограничен 2 МБ до парсинга; ограничены длины полей, количество занятий и исключений. Версия схемы проверяется явно. Поддерживается только `para-schedule` v1, а не произвольный JSON старого сайта.

## UI и процессы

Compose → `ParaViewModel` → `ScheduleEdits` / `ScheduleRepository`.

Виджет может запускаться отдельно, до загрузки Flow. Поэтому читает тот же атомарный файл, а не начальное пустое состояние ViewModel. Никаких HTTP-запросов внутри receiver. `PendingIntent` immutable, дата передаётся отдельным extra и уникальным URI. Receiver не экспортирован.

## Размеры виджета

`WidgetSizing` выбирает облегчённые колонки, обычные колонки, компактные строки или полные карточки по размеру и масштабу шрифта. Учитываются реальные font metrics, а не предположение, что sp равен dp. Ширина для текста учитывает отступы и поля карточки.

Все макеты используют прямой `RemoteViews`-биндинг. Прокручиваемой коллекции больше нет: она допускала обрезание рамок на верхнем/нижнем крае. Вертикальные карточки получают равные ограниченные слоты через weight. Калькулятор выбирает количество слотов, число строк названия и наличие дополнительной строки. Подробности не помещаются — скрываются целиком, а не выдавливают время/название за рамку. Для физически очень низкого виджета ограничивается размер основного текста. Полный текст остаётся в accessibility description и в приложении.

Пустой день явно скрывает контейнер занятий. Заголовки single-line и ellipsize. Если все пары не влезают, отображается «Ещё N»; фокус по возможности остаётся на текущей/ближайшей паре. В ультранизком варианте подвал скрыт ради времени и аббревиатуры.

## Адаптивное приложение

Material You применяется через `dynamicLightColorScheme` / `dynamicDarkColorScheme` и семантические роли цветов. Новые профили используют системную палитру по умолчанию на Android 12+, старый явный выбор сохраняется. На Android 8–11 остаётся фирменная fallback-палитра. Изменения конфигурации участвуют в ключах выбора темы.

При ширине окна от 720dp используется NavigationRail; содержимое ограничивается 960dp. В узких окнах/при большом шрифте карточка занятия становится вертикальной, действия переносятся, декор не отнимает место у текста, кнопки растут по высоте. Полоса недели и сетка месяца могут прокручиваться горизонтально, сохраняя читаемые даты. Диалог выбора даты — Material 3, с режимом ввода на узком экране или при крупном шрифте.

Палитра виджета: светлая/тёмная fallback на Android 8–11, системные Monet-ресурсы на 12+. Тема самого приложения независима и может следовать системе или выбираться вручную.

## Намеренные ограничения первой версии

- Одна локальная группа, без аккаунтов, сервера, автосинхронизации и уведомлений.
- Распознавание PDF/фото/XLSX/текста пока отсутствует.
- Конфликты времени в редакторе запрещены для одного шаблона/дня. Подгруппы и параллельные занятия ещё не моделируются.
- JSON валидируется структурно; импорт может содержать пересечения, которые нужно исправить вручную. Никакие записи молча не удаляются.
- Обновления виджета best-effort, не точные будильники.
- Копия recovery лежит в private storage; автоматического UI восстановления повреждённых данных пока нет.
