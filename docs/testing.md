# Проверка приложения

## Автоматически

```bash
./gradlew testDebugUnitTest lintDebug assembleDebug
./gradlew connectedDebugAndroidTest   # отдельный эмулятор / тестовое устройство
```

JUnit-тесты проверяют вычисление недель и чётности, границы периода, приоритет исключений, воскресенье → понедельник, часовые пояса, интервал [начало, конец), аббревиатуры, пересечения и безопасный JSON roundtrip.

## Локальный AI (0.2)

JVM-набор расширен до 63 тестов: подбор моделей, ручной выбор вне автоматического RAM-tier, ограничения памяти/диска/ABI, диапазоны недель, даты без года, запрет догадок о звонках, исправление пропущенных моделью явных заголовков недель, конфликты и режимы применения.

`LocalAiIntegrationTest` действительно запускает llama.cpp с GGUF Qwen3 0.6B, проверяет JSON/поля и формирует две недели. Отдельно проверяются русский OCR, PDF, DOCX/XLSX (включая Excel-время) и отказ от внешних XML-сущностей. `AiImportUiTest` проверяет выбор моделей, черновик без автоматического сохранения, применение и откат.

OCR/LLM-тестам нужны скачанные пакеты в private storage тестовой debug-версии; при их отсутствии соответствующие тесты помечаются `skipped`, что не является подтверждением работы распознавания. Используйте отдельный 64-битный эмулятор с достаточной RAM. Первичный реальный прогон маленькой модели выполнен на Android 15 / x86_64 с двумя CPU-потоками; это не benchmark физических телефонов или моделей 1.7B/4B.

Проверка сетевых загрузок включается **только явно**:

```bash
adb -e shell am instrument -w -e networkAssets true -e class app.para.schedule.AiDownloadTest app.para.schedule.test/androidx.test.runner.AndroidJUnitRunner
```

Этот тест загружает OCR-пакет через DownloadManager, проверяет SHA-256 и начинает/отменяет загрузку GGUF после получения первых данных. Он временно меняет пакеты тестового приложения и использует интернет; на личном устройстве его запускать не следует.

Android-тесты проверяют создание занятия через UI, переходы между экранами и тёмную тему. Отдельный тест действительно применяет `RemoteViews`, измеряет и рисует виджеты в размерах 110×70, 110×150, 260×70, 260×120 и 300×300dp. Это важно: успешная компиляция XML ещё не гарантирует, что лаунчер сможет отобразить класс View.

Регрессия адаптивности: 10 размеров виджета × 4 масштаба шрифта (100/130/180/200%) × 2 темы. Проверяются границы **каждой** карточки и каждого видимого текстового поля, отсутствие вертикального клиппинга и скрытие кабинета при нехватке места. Для приложения отдельно проверяются узкие карточки/заголовок при 100/130/200% и соответствие цветовых ролей системной палитре Material You в светлой и тёмной темах.

Инструментальные тесты заменяют локальные данные debug-приложения. Не запускайте их на рабочем расписании. PNG тестовых виджетов сохраняются в private `filesDir` debug-приложения и могут быть извлечены через `adb exec-out run-as app.para.schedule cat files/widget-260x120.png`.

Gradle может удалить тестовое приложение после прогона. Чтобы оставить PNG для просмотра, можно установить тесты вручную на эмулятор:

```bash
./gradlew assembleDebug assembleDebugAndroidTest
adb -e install -r app/build/outputs/apk/debug/app-debug.apk
adb -e install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -e shell am instrument -w app.para.schedule.test/androidx.test.runner.AndroidJUnitRunner
adb -e exec-out run-as app.para.schedule cat files/widget-260x120.png > widget.png
```

## Перед широким распространением

Проверка обновления 24.10.2026: **30 JUnit-тестов и 8 инструментальных тестов прошли**, Android Lint — без ошибок (есть предупреждения). Матрица 80 сочетаний размеров/шрифтов/тем, узкие карточки приложения и диалог даты с крупным шрифтом проверены на AOSP-эмуляторе Android 15 / API 35. Совместимость с MIUI/HyperOS и аппаратами Android 8–11 не проверена на физических устройствах — это остаётся отдельным этапом.

Дополнительно вручную проверены полное приложение при ширине 320dp и шрифте 200%, а также широкое окно 1280×800dp с боковой навигацией. Скриншоты находятся в `docs/screenshots/adaptive/`.

Подписанный APK 0.1.5 установлен поверх release 0.1.3 на эмуляторе: сохранённые группа и расписание остались на месте, подпись совпала. SHA-256 скачанного APK проверен по опубликованному файлу.

- Физический Android 8–11: проверить прямые карточки и fallback-палитру.
- Физический Android 12+: смена обоев и светлой/тёмной системной темы.
- MIUI/HyperOS: реальные размеры 4×1 / 4×2 / 2×2, отсутствие серой полосы после ресайза.
- Добавление через pin-запрос и вручную; нажатие на карточку открывает правильную дату.
- Перезагрузка, полночь, воскресенье, смена часового пояса телефона: календарь группы не должен сдвигаться в другой пояс.
- Battery saver/Doze: допустима задержка фонового обновления; ручная ↻ должна работать.
- Большой системный шрифт, TalkBack, небольшой дисплей и поворот экрана.
- JSON: экспорт, импорт на втором устройстве, отказ от замены, неверная версия, файл > 2 МБ, повреждённый JSON.
- Обновление подписанного release поверх предыдущего без потери расписания. Debug и release не взаимозаменяемы по подписи.
- Разовая отмена и редактирование не должны изменять следующие недели. Изменения шаблона не должны затирать исключения.

Проверка на одном AOSP-эмуляторе не заменяет проверки поведения виджетов на реальных лаунчерах производителей.
