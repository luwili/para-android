# Автоматический импорт: реализация и следующие этапы

## Реализовано в ветке 0.2

Локальный llama.cpp, три Qwen3-модели с авто- и ручным выбором, отдельные загрузки с SHA-256, OCR русского/английского текста, PDF/DOCX/XLSX/CSV/TXT, редактируемый черновик, проверка и распределение по неделям, подтверждение и восстановление предыдущего расписания. Текущие возможности и пределы: [local-ai.md](local-ai.md).

Ниже сохранён принцип проектирования. Следующие задачи — собрать реальные обезличенные примеры, измерить качество всех трёх моделей на физических телефонах, улучшить извлечение сложных таблиц и при необходимости добавить проверенное аппаратное ускорение. Серверная синхронизация — отдельная задача.

## Рекомендация

Не вшивать LLM в базовый APK. Сначала сделать **импорт → черновик → проверка → подтверждение**, а движок распознавания подключать отдельно. Мощный телефон не гарантирует достаточно свободной RAM, поддержку GPU/NPU и приемлемое время обработки документа.

## Надёжный конвейер

1. **Получить файл** через SAF: XLSX/CSV, текстовый PDF, фотография или вставленный текст. Для ссылки университета нужен отдельный адаптер и явное согласие на сеть.
2. **Извлечь структуру** детерминированно: CSV/XLSX parser; текст PDF; OCR для сканов и фотографий. LLM не заменяет OCR изображения.
3. **Распознать правила**: группа, даты, дни недели, интервалы, чётность, границы месяца, учебный год, переносы и отмены. Определить формат документа, а не пытаться угадать всё одним prompt.
4. **Нормализовать** в `ImportDraft` со списком источников, непонятных полей и конфликтов. Время, год, группа и дубликаты проверяются кодом.
5. **Показать предпросмотр** недели/месяца. Неизвестный год, «числитель/знаменатель», неоднозначные диапазоны и отсутствующие звонки требуют подтверждения студента.
6. **Применить атомарно** только после подтверждения. Предложить создать резервную копию и выбрать: заменить всё, заменить даты или дополнить без конфликтов.

`ImportDraft` должен быть отдельной моделью: сырой текст никогда не отправляется прямо в `ScheduleRepository`. Логи без ФИО и исходного документа.

## Что делать с неделей и месяцем

- Есть конкретные даты — записывать в `overrides` именно эти даты.
- Есть недатированная недельная таблица — предложить пользователю период действия и тип EVERY/ODD/EVEN.
- Есть только «неделя 8» — запросить понедельник первой учебной недели или конкретную дату этой недели.
- Есть «по 30 ноября» — подтвердить год и обе границы.
- Есть строка «пар нет» — создавать явное пустое исключение, а не пропускать её.
- Нет уверенности в чётности или годе — **не додумывать**.

## Локальная LLM: опциональный ускоритель

Подключена после OCR/извлечения текста, с ограничением ответа GBNF и отдельным валидатором. Качество нужно измерять на русскоязычных расписаниях; объём параметров сам по себе не гарантирует правильность. Веса занимают от сотен мегабайт до нескольких гигабайт, runtime требует дополнительной памяти и может заметно нагревать телефон.

Лучше отдельная загрузка «Офлайн-распознавание» по желанию: заранее показать размер, требования к памяти, проверить SHA-256 весов, дать удалить модель, работать без неё и никогда не загружать документ в облако без явного выбора. Размер модели и скорость зависят от квантизации и backend; обещать совместимость со «всеми мощными Android» нельзя.

Сравнить подходящие runtime (например, llama.cpp / доступные Android LLM SDK), поддержку ABI и ускорения, лицензии и реальный пик RAM. На слабых устройствах остаётся детерминированный импорт/ручной редактор. Любая LLM может ошибаться и галлюцинировать: предпросмотр обязателен независимо от confidence.

## Порядок реализации

1. Собрать 10–20 обезличенных реальных расписаний разных вузов.
2. Начать с текста/CSV/XLSX + предпросмотра; покрыть извлечение дат и звонков тестами.
3. Добавить PDF и OCR фотографий с управляемой загрузкой моделей.
4. Замерить качество и только затем решать, нужна ли LLM и какая.
5. Если группе нужна актуализация «у всех сразу» — отдельно спроектировать публикацию и подписку на группу. Это другая задача, не решаемая локальной LLM.
